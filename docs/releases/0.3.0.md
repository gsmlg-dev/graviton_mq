# GravitonMQ 0.3.0

This release fixes the High and Medium findings of the 2026-11-08 repository
review. It removes the local WAL lifetime cap, closes an AMQP decoder memory
amplification, narrows AMQP broker fault domains and corrects MQTT CONNECT and
session-takeover handling. All seven packages retain the same version and
exact internal dependency requirements.

## Upgrade notes

- **WAL format is forward-only once compacted.** A log that has never been
  compacted keeps the 0.2.x single-file format byte-for-byte. After its first
  compaction a durable directory uses `events.<n>.wal` generation files and a
  version 2 checkpoint, which 0.2.x cannot open. Do not downgrade a durable
  directory after 0.3.0 has compacted it.
- **MQTT expiry-0 session takeover changed.** When a new connection takes over
  a client whose session expiry is 0, that session now ends (MQTT 5
  §3.1.2.11.2): the old Will becomes due and the new connection receives
  Session Present 0 with a fresh session. Previously the session was resumed.
  Takeover of a session with a non-zero expiry still resumes it.
- **AMQP Begin windows.** The `:ambiguous_session_window` connection error no
  longer exists; any uint incoming/outgoing window is accepted.

## Fixes

- **AMQP decoder:** zero-width array elements (constructors 0x41–0x45) are
  charged against a cumulative budget, `Codec.Limits.max_zero_width_elements`
  (default 65,536), shared across nested containers, message sections and
  annotation checks. A small frame can no longer expand into hundreds of
  millions of values. `Codec.Value.decode_bounded/3` exposes the remaining
  budget.
- **AMQP sessions:** in-flight Flow and Transfer frames for a Link after a
  clean local Detach are tolerated until the peer's Detach and still count
  against the Session window and delivery-ID sequence. Input after an error
  Detach still ends the Session with `errant-link` (§2.6.5).
- **AMQP broker:** an unanswered or uncertain lease/status queue call fences
  only that queue. Its claims return for redelivery, its Links are detached
  with `amqp:internal-error`, new attaches are refused, and it is restored when
  it answers again; the Broker and other queues keep running. A briefly busy
  Connection is retried instead of closed, and socket input is event-driven
  (`active: :once`) instead of polled every 5 ms.
- **Durable storage:** the WAL compacts atomically (one checkpoint rename is
  the commit point, positions stay monotonic). MQTT compacts to its latest
  snapshot and each AMQP queue to a snapshot of its live state. Compaction
  runs at half of `max_log_bytes`, on open and on a log-limit append, so
  `max_log_bytes` bounds live state rather than lifetime traffic, and a broker
  stuck at the limit can restart. Recovery truncates an invalid tail beyond
  the durable boundary and reinitializes a log interrupted before its first
  checkpoint.
- **MQTT broker:** packets sent immediately after CONNECT are held while
  authentication is outstanding, replayed in order after CONNACK and discarded
  if CONNECT is rejected (MQTT-3.1.4-6). The hold is bounded by Receive
  Maximum packets and Maximum Packet Size bytes; overflow refuses CONNECT with
  0x97. Takeover resumes only the post-disconnect session, so stale delivery
  markers can no longer stall a resumed session.
- **MQTT client:** a persistent client rewrites its checkpoint only when
  retained content changes, not on every keepalive tick, and a transport loss
  releases its socket and timers.
- **Release workflow:** runs for one version queue instead of cancelling each
  other; the version commit and tag are pushed before Hex publication, and a
  re-run resumes an interrupted publication from the existing tag.
