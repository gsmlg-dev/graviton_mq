## Partial-publication recovery

The [first workflow](https://github.com/gsmlg-dev/graviton_mq/actions/runs/40994823411)
published core, then stopped because the next staged project lacked fetched
dependencies. The repair fetches dependencies before publishing and accepts
an existing version only when its SHA-256 matches the verified local archive.
The actual shell accepted identical public content and rejected changed
content; the dependent package's dry-run passed after dependency resolution.
The successful workflow verified the existing core publication and published
the remaining six packages. No version replacement was needed.

The [support matrix](../CAPABILITIES.md), [release notes](../releases/0.2.0.md)
and clause audits retain selected-profile boundaries. This evidence does not
establish universal conformance, production throughput or hardware power-loss
qualification. MQTT QoS2 is not a business exactly-once guarantee, and memory
acceptance is not disk durability.
