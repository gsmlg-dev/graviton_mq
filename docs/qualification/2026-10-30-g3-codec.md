## Transport/message schema integration

The later increments pass **309 AMQP tests, zero failures**. Independent
read-only cross-review identified custom distribution-mode whitelisting,
empty supported-dist-modes, and forbidden content-encoding combinations/identity.
Each defect was reproduced before repair and has a deterministic regression.
The repaired files were independently rechecked: 50 repository Attach/Terminus/
DeliveryState tests plus three review regressions, and 52 delivery/message tests,
all passing, with no remaining Important or Critical findings identified.

All eight commands listed in the integrated G2 record were rerun against the
final combined schema source using Elixir 1.18.4 / OTP 28.5.0.1 and
`ERL_FLAGS='+S 4:4'`: **612 tests, zero failures**, including all 25 explicitly
enabled MQTT external-peer tests. Compilation had zero warnings; architecture
analysis covered **3,986 source references across seven applications** and
xref found no cycles. Counts are core 9, AMQP 309, MQTT 191, storage 3, client
22, runtime 21 and public composition 57. Logs are
`/tmp/graviton-goal-20261029-v4ozpgqs/g3-schema-gate-01.log` through `08.log`.
The old unknown-performative test used Attach as a sentinel; it now uses an
actually unsupported descriptor while retaining the same failure assertion.

Transfer keeps omitted settled distinct from explicit false. The endpoint,
not the codec, must enforce first/continuation fields, fragmentation, credit,
sequence ranges and settlement. Incoming noncanonical Error and Modified
annotation encodings remain available for core mapping; canonical re-encoding
does not replace their source provenance. A parsed Message cache never
replaces the authoritative encoded content. New-message construction preflights
its total encoded size before any child binary allocation.

The message parser accepts empty/header-only section streams without inventing
a body. An independent black-box check with python-qpid-proton **0.40.0**
accepted both and its default Message encoder generated header+properties
without a body. This supports the bounded parsed-view behavior; it is not
network-role or complete message-profile qualification. Application-properties
remain scalar/null only, arrays symbol-only and unknown top-level sections or
delivery states explicitly unsupported. Nested extension data is preserved as
data, without accepting its negotiated endpoint semantics. Transactions remain
outside the profile.

## Prepared independent AMQP peers

Apache ActiveMQ Artemis **2.41.0** official binary SHA512 was verified before
starting two separate temporary instances. Each used one OS-selected loopback
AMQP-only port with web/JMX/security/persistence disabled; raw AMQP1 protocol
headers were exchanged over real sockets. Instances stopped and were removed,
and the ports were reusable. Runtime was OpenJDK 21.0.12.1+1. Fixture setup,
immutable checksum, logs and cleanup evidence are under
`/tmp/graviton-goal-20261029-v4ozpgqs/artemis-peer/`. The container route failed
because the rootless runtime tmpfs was full; no existing resources were removed,
and the verified binary route qualified this test infrastructure instead.

python-qpid-proton **0.40.0** is installed only in the task-local
`/tmp/graviton-goal-20261029-v4ozpgqs/proton-review-env`. Neither peer is a
production dependency. These are fixture/header and codec observations;
Graviton AMQP client↔Artemis and Qpid Proton↔Graviton broker remain NOT RUN.

Frame encoding requires the existing struct's declared size/offset to match
its bytes; it does not infer or rewrite inconsistent metadata. Header and body
remain opaque. SASL frames are explicitly unsupported. Arrays remain
symbol-only; floating-point/decimal/char wire support remains outside this
increment. Flow is protocol data: credit, sequence windows and Session/Link
transitions are not implemented by its codec.
