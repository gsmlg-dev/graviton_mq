# GravitonMQ 0.2.1

This maintenance release fixes AMQP broker backpressure handling and MQTT
client admission when local persistence is enabled. All seven packages retain
the same version and exact internal dependency requirements.

## Fixes

- An AMQP broker waits for temporary sender capacity to recover instead of
  detaching a consumer whose next message fits the Link's permanent limits.
  The pending message retains its queue responsibility and order. Messages
  exceeding permanent limits still receive an explicit refusal.
- AMQP fragmentation waits for sufficient writer capacity without exhausting
  fragment slots on temporary leftovers. Capacity reserves the largest
  delivery-ID encoding so another Link cannot invalidate a pending message's
  limit; impossible sends complete with an explicit error.
- A persistent MQTT client rejects shared subscriptions before allocating an
  operation or sending SUBSCRIBE, returning
  `{:error, :shared_subscription_persistence_unsupported}`. A successful SUBACK
  can no longer turn this unsupported request into a checkpoint failure and
  close the client. Ordinary subscriptions remain usable; memory clients
  retain their existing peer-capability checks.

## Scope

The [capability matrix](../CAPABILITIES.md) retains the selected AMQP 1.0 and
MQTT 5.0 profiles. This release adds no shared-subscription persistence,
protocol resumption, clustering, or other protocol feature. Historical
qualification records remain tied to their original versions.

Release verification and public artifact checks are recorded in the
[0.2.1 qualification record](../qualification/2026-11-08-v0.2.1-release.md).
