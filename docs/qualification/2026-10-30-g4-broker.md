## Independent Qpid Proton path

python-qpid-proton **0.40.0**, CPython **3.12.13** and OpenSSL **3.6.3**.
They connect to our broker with no product client code imported:

1. A 100 KB binary publication and independent reception through our broker,
   with a 512-byte frame limit and exact length/SHA256 verification.
2. Zero receiver credit leaves the message ready, with no inflight claim;
   an explicit peer credit gate then allows delivery and acceptance.
3. Released causes actual redelivery before Accepted retires the message.
4. Receiver disconnection with an unsettled delivery returns responsibility;
   a second independent receiver gets the original message.
5. Durable publication and unknown address attachment fail explicitly.
6. Two embedded instances have different actual listeners and independent
   memory queues, including a real exchange on only one instance.
7. Modified changes delivery-count and message annotations on redelivery;
   a separate Rejected delivery is discarded.
8. Verified TLS exchanges succeed with the trusted CA and fail with another

## Review repairs

Independent review reproduced and repaired these boundaries:

- A Queue monitoring the Connection could process DOWN before the Manager's
  final known outcome. The Queue now monitors the settlement coordinator.
  The old ownership deterministically requeued a known Accepted; coordinator
  ownership retired it. The suspended-Manager independent-peer test locks the
  integrated behavior down.
- Logical queue charges were compared with AMQP wire bytes. A valid 500-byte
  message could stall forever under a 512-byte receiver limit. Claims now use
  bounded logical charges and separately bound the outbound wire view.
- Small configured queues could never grant credit because the receive
  reservation still assumed 1 MiB. Their advertised inbound limit now respects
  configured queue capacity; the 4 KiB/1 KiB regression exchanges real messages.
- Uncertain registration/disconnect cleanup could leave an orphan lease.
  The Manager now fails explicitly so queues reclaim its residual leases.
  A suspended-Queue/native-Detach test verifies actual surviving-state redelivery.
- Pump limits counted only successful actions. Waves now bound inspected
  routes, including zero-credit routes; a stalled Connection cannot impose
  five seconds of blocking per Link on healthy work.
- Async socket closure could beat the final Close response. The shell waits
  for that Writer receipt under a finite deadline. Startup now passes the
  command handle directly, so a TLS handshake does not block the Manager.
- OTP debug rings include messages and callback state outside `format_status`.
  Bounded opaque ETS handoffs and private retained state protect both those
  rings and sanitized failure reports, with actual debug/crash regressions.

The first full gate attempt also exposed test integration defects: the core
export assertion assumed another async test had loaded the module, and a new
runtime test reused an older protocol test module name. Explicit module load
and a distinct runtime test name repair both without reducing assertions.
First-attempt logs remain in `g4-network-first-gate-*`.

## Limits and next stage

This is the intermediate single-node memory profile, not full AMQP
conformance or durable recovery. It supports non-dynamic volatile move queues,
format zero, no SASL, unsettled senders and receiver-first settlement.
Other termini/required capabilities, durable and expiry-bearing messages,
dead-letter actions and transactions are rejected or unsupported explicitly.
Arrays remain symbol-only. Queue loss loses memory; surviving-queue cleanup
and peer redelivery are not WAL recovery. The [broker guide](../AMQP10_BROKER.md)
records configuration, bounds and failure semantics.

G5 retains MQTT QoS2 and mandatory/conditional protocol completion, plus
AMQP flow/settlement/serial/disconnect evidence. G6 requires actual WAL/sync/
streaming recovery and durable-through acceptance. G7 requires all four peer
paths in CI and resource/model/fuzz/soak/install qualification. MQTT3.1.1
CONNECT/CONNACK codec regressions remain separate from any future legacy runtime.
No branch/worktree, commit, push, release, publication or deployment occurred.
