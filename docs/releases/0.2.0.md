# GravitonMQ 0.2.0

This release adds four native network roles: AMQP 1.0 broker and client,
and MQTT 5.0 broker and client. Brokers support standalone startup and
embedding in a host OTP supervision tree. The independently installable
`graviton_mq_client` package starts no broker and depends only on core types
and the two pure protocol libraries.

## Shipped behavior

- MQTT 5.0 QoS0/1/2, topic matching, sessions, retained publications, Will and
  expiry, bounded host/network operations, explicit authentication and
  authorization callbacks, TCP and verified TLS, keep alive and controlled
  client reconnect.
- AMQP 1.0 semantic values, frames, transport performatives, message sections
  and outcomes, pure Connection/Session/Link transitions, bounded credit and
  windows, fragmented transfer, settlement, release/redelivery and named queues
  over TCP/TLS. Original encoded messages and independent local/remote
  channels/handles are preserved.
- Single-node memory and opt-in Linux local durability profiles, with a real
  checksummed WAL, separate append/sync/durable-through boundaries and
  streaming recovery. Durable acceptance follows the selected sync boundary;
  failed and uncertain results remain explicit.
- Seven packages with synchronized versions and exact internal dependencies:
  `graviton_mq_core`, `graviton_mq_storage`, `graviton_mq_amqp10`,
  `graviton_mq_mqtt`, `graviton_mq_client`, `graviton_mq_runtime`, `graviton_mq`.

## Profile boundaries

These are bounded selected-profile results, not universal protocol conformance
or production throughput, security or hardware power-loss qualification.
MQTT QoS2 does not establish business exactly-once delivery; a memory ACK
does not establish disk durability.

MQTT topic aliases, shared subscriptions and subscription identifiers are
negotiated off; enhanced authentication is refused. Historical MQTT 3.1.1
CONNECT/CONNACK codec regressions remain, with no qualified legacy runtime.
The AMQP client has no SASL, link resumption or process/VM recovery. Unsupported
dynamic/durable termini, filters and TTL/absolute expiry profiles are refused
as documented in the matrix. Clustering/Raft, management UI, cross-protocol
bridges, AMQP transactions and QUIC remain outside this release.

The qualified toolchain is Elixir 1.18.4 and Erlang/OTP 28.5.0.1, as declared
in `.tool-versions`.
